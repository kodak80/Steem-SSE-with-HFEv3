Steem SSE 4.2.1 (r1511) with HFEv3 support
===========================================

Unofficial build of Steem SSE from the SourceForge "V4.2.1 Releases"
branch (r1511), adding support for HFE v3 floppy images ("HXCHFEV3", as
written by the HxC Floppy Emulator software and used by FlashFloppy and HxC
hardware). Source: https://github.com/kodak80/Steem-SSE-with-HFEv3

What's new in HFEv3-7
- Fuzzy bits from real disks (Greaseweazle / FloppyBridge): Dungeon Master
  originals now pass their protection - the gate out of the Hall of
  Champions opens. Its sector 7 holds 489 bytes written so that each reads
  $68 or $E8, and the game checks both that only those values come back and
  that two reads differ. The drive's electronics show only a byte or two of
  them changing, so Steem now makes only the bit cells that change random
  (a byte keeps the values it can really take) and applies them to the
  whole run of identical bytes around them.
- More reliable re-reads: when a sector is bad, Steem now waits for
  genuinely new revolutions of the disk (up to 4) instead of sometimes
  getting the same one twice.
  Confirmed: Dungeon Master (original), Total Recall disks 1 and 2
  (Copylock still passes).

What's new in HFEv3-6
- Swapping real disks (Greaseweazle / FloppyBridge). Just change the disk
  in the drive while it's quiet, like on a real ST - no need to eject and
  re-insert Greaseweazle.hfe any more. Steem notices the change from the
  drive's disk-change line (if it has one), from the write-protect sensor
  (as the ST itself does), and by checking the disk again after the drive
  has been idle; the ST then sees a disk change and everything read from
  the old disk is dropped. Wait for the drive to go quiet before taking a
  disk out, so tracks the ST wrote to are saved first.
- Weak bits. When a sector has a bad CRC, more revolutions are read: if the
  sector reads correctly on one of them, that copy is used; if it's bad
  every time and changes from one revolution to the next, the bytes that
  change read differently each time the ST reads them, as on the real disk.
  A sector that's bad but always the same (a deliberate CRC error, as in
  Copylock or UN Squadron) is left as it is.
- Greaseweazle.log shows disk checks, write-protect changes, the tracks the
  ST reads after a disk change, and more detail on bad sectors.
  Confirmed: Total Recall disk 1 -> disk 2 swap, Copylock still passes,
  Dungeon Master (copy) loads and plays, UN Squadron's protection track.

What's new in HFEv3-5
- Writing to real floppy disks (Greaseweazle / FloppyBridge). Add write=on
  to Greaseweazle.hfe and what the ST writes goes to the real disk: saved
  games and high scores, files and folders from the desktop, formatting a
  blank disk. Off by default: without write=on the disk stays read-only
  (write-protected for the ST), and a disk with its write-protect tab set
  is always write-protected.
  How it works: the Greaseweazle can only start a write at the index hole,
  not at a given sector, so a track the ST changes is rewritten whole - the
  track as Steem read it, with the ST's changes - starting in its largest
  gap so the join falls between sectors. It's written when the head moves
  to another track, when the ST's drive motor stops, when Steem stops and
  on eject, then read back and every sector checked (written again if
  needed). Greaseweazle.log shows each track written and verified.
  Use copies, not originals: the track is rewritten at the normal density,
  so a density copy protection (Copylock) on a track the ST writes to would
  be lost - a real ST only rewrites the sector it changes. Tracks that
  couldn't be read aren't written unless the ST formats them.
  Confirmed: formatting, folders, saving the desktop, write-protect, Crazy
  Cars high scores.

What's new in HFEv3-4
- Real floppy drives: a drive connected to a Greaseweazle (or a DrawBridge or
  SuperCard Pro) can now be used as Steem's drive A: or B:, so you can boot
  your original disks directly - copy-protected ones included. It uses Rob
  Smith's FloppyBridge, the same driver as WinUAE and DiskFlashback.
  Setup:
  1. Download FloppyBridge from https://amiga.robsmithdev.co.uk/winuae and
     put FloppyBridge_x64.dll (Steem64) or FloppyBridge.dll (Steem32) next to
     the Steem exe.
  2. Close DiskFlashback, or release the drive from it (only one program can
     use the Greaseweazle at a time).
  3. Insert Greaseweazle.hfe (included) in A: from the disk manager, like a
     disk image, and press Play. It's a small text file you can edit: serial
     port, drive A or B, and a few options. See README-FloppyBridge.txt.
  How it works: each track is read from the drive when the ST needs it (the
  emulation pauses for a moment, the ST doesn't notice) and checked sector by
  sector, re-reading if needed. FloppyBridge measures how fast the data goes
  past the head, so density-based protections see the real disk's timing:
  Rob Northen Copylock passes from the original disk (Total Recall's slower
  sector measured 5.5% slower). The drive only spins while the ST reads it,
  as on a real ST. A log (Greaseweazle.log, next to Greaseweazle.hfe) shows
  each track read, its sectors and the measured speeds.
  Confirmed with: Road Blasters (KIXX), Backlash, Total Recall disks 1 and 2
  (Copylock), UN Squadron.
  Limits: read-only in HFEv3-4 (see HFEv3-5 for writing); to swap the real
  disk, eject and re-insert Greaseweazle.hfe so the ST sees the change; one
  revolution is kept per track, so protections relying on weak bits reading
  differently each time may not pass; Windows only.
  Disk images are unaffected.

What's new in HFEv3-3
- ReadySoft-style loaders that read a run of sectors in one go (READ MULTIPLE)
  over a track containing a deliberate bad-CRC sector now work. Steem used to
  end the whole read at the bad sector; the real WD1772 flags the error and
  keeps reading to the end of the run, which these loaders depend on. This gets
  several protected titles much further than before. (Note: Dragon's Lair /
  Dragon's Lair 2 now load their first tracks but still stop later on a
  separate track-6 check - not yet solved; they work on a real Gotek.)
  Ordinary disks are unaffected - only multi-sector reads that hit a CRC error.

What's new in HFEv3-2
- Rob Northen Copylock (and other density-based protections) now work. Copylock
  reads two sectors of a track and requires the protected one to read slightly
  slower - it's written at a lower density. Steem's HFE reader timed every byte
  at the fixed track-average rate, so that check always failed and protected
  games reached the title screen and then rebooted. HFE v3 tracks whose cell
  density varies are now timed cell by cell, so a slower sector reads slower,
  just like on a real drive. Confirmed on Xenon II, Toki, Roller Coaster
  Rumbler and The Chaos Engine; also improves timing-sensitive in-game checks
  (e.g. the Dungeon Master Hall of Champions gate). Ordinary disks are
  unaffected (only tracks with varying density use the new timing).

Earlier (HFEv3-1)
- HFE v3 images can be inserted like v1 HFE images.
- FIX for all HFE images (v1 too): images made by HxC, Gotek or GTi didn't
  boot (TOS kept retrying the boot sector, Record Not Found). Their sync
  marks don't fall on 16-bit word boundaries, which Steem's word-based HFE
  reader needed. HFE images now always use Steem's bit-level (DPLL) reader.
- FIX: writing a sector to an HFE image could land a few bits off and wreck
  the sector's own header (games saving high scores, e.g. Crazy Cars, left a
  broken save that hung on the next boot). Delete any .sav.hfe made by an
  earlier test build.
- v3 opcodes are handled: index position, bit rate changes, skipped bits and
  random (weak) bits. Weak bits read differently on each revolution.
- Save copies, like the GTi Gotek interface: writing to an HFE image (v1 or
  v3) never changes the original. When the disk is ejected or Steem is
  closed, the changes are saved as Game.sav.hfe beside Game.hfe, and from
  then on inserting Game.hfe loads Game.sav.hfe instead. Delete the .sav.hfe
  file to go back to the original. A .sav.hfe inserted directly is updated
  in place.
- v3 images are saved in v3 format. A written track can't grow beyond the
  space it already has in the file.
- HFE v1 images otherwise behave as before.

Notes
- This build is made automatically from the author's VS2019 project
  (Steem.vcxproj, Steem-D3D-Release) with the VS2019 compiler, not with
  VS2008 like the official releases, so it needs Windows 7 or later.
- Steem64-HFEv3.exe is the 64-bit build, Steem32-HFEv3.exe the 32-bit one.
- Only Steem itself is included, plus Greaseweazle.hfe and
  README-FloppyBridge.txt for real drives (FloppyBridge's DLL is not
  included: download it as described above). For optional extras
  (plugins, DLLs for IPF or archive support, etc.), copy this executable
  into an existing Steem SSE 4.2.1 folder.
